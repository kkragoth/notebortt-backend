# Adversarial Review of the Modernization Plan

> Review stance: assume every claim is wrong until verified against the repo.
> Each finding lists severity, evidence, and **disposition** (how the plan docs
> were changed in response). Findings marked *accepted* drove concrete edits;
> *rejected* ones explain why.

## Verdict

The phased direction (modular monolith → K8s → Terraform → ArgoCD → brokers) is
sound, but the original plan contained **five plan-breaking technical bugs**
that would fail on day one, several internal contradictions, and a strategic
gap: it never justified the cost/ops jump against team reality, and its exit
criteria measured activity, not outcomes. All critical/high findings are now
fixed in the phase docs.

---

## CRITICAL — plan-breaking

### C1. The migration Job cannot run · *fixed*
`npx drizzle-kit migrate` runs on the app image, but the Dockerfile runner
stage does `npm ci --omit=dev` and `drizzle-kit` is a **devDependency** →
command fails instantly. The old compose `migrator` worked only because it ran
`npm ci --include=dev` on a bare node image.
**Disposition (02):** drizzle-kit moved to production `dependencies`; migration
strategy switched from a racing Job to a per-pod **initContainer** (see C2/C4);
exit criterion verifies ordering empirically.

### C2. Phase 1 promised ordering Kustomize cannot deliver · *fixed*
Exit criterion said "migrations run as Job *before* new pods become ready."
Plain `kubectl apply -k` gives no hook mechanism; `argocd.*` annotations are
inert outside ArgoCD, so Job and Deployment race.
**Disposition (02):** initContainer with `pg_advisory_lock` performs migrations
inside every app pod start — guaranteed ordering, idempotent, works without
ArgoCD. ArgoCD PreSync demoted to an *option* evaluated in phase 3, not an
assumption baked into phase 1.

### C3. `runAsNonRoot: true` on a root-default image → CrashLoopBackOff · *fixed*
node:22-alpine defaults to root; Dockerfile had no `USER`.
**Disposition (02):** Dockerfile gains `USER node`; securityContext kept and
now consistent.

### C4. Migrate Job double-management + immutability trap · *fixed*
Job lived in the Kustomize base *and* carried ArgoCD hook annotations. Jobs are
immutable across applies; any spec change makes subsequent applies error, and
ArgoCD would fight Kustomize ownership.
**Disposition:** resolved by C2's initContainer choice; hook manifests, if ever
adopted, live only under `gitops/`, never in `k8s/base`.

### C5. RabbitMQ per-message TTL dead-lettering has head-of-line blocking · *fixed*
Preview deferral produces *variable* delays (90s debounce, up-to-180s
min-interval deferral). With TTL→DLX, a longer-delayed message ahead blocks
shorter ones behind it — classic RabbitMQ pitfall; renders would be late.
**Disposition (05):** switched to the `rabbitmq_delayed_message_exchange`
plugin (or delay-bucket queues as fallback); noted quorum-queue `lazy` flag is
obsolete in RabbitMQ 4.x.

### C6. dependency-cruiser rule banned the pattern it was meant to allow · *fixed*
Mixing capture groups in both `from.path` and `to.path` made `$1` ambiguous,
and `pathNot` exempted only the *from*-module's own index — i.e. the rule
flagged legitimate `import … from '../boards/index.js'` barrels.
**Disposition (01):** replaced with N trivially-correct rules generated by a JS
loop (one per module: "import module X only via X/index.ts"). Interim rules now
also target the **current** layout, since the big directory move was descoped
(see M1).

### C7. Manifest shipped `replicas: 2` while its own caveats said don't · *fixed*
Presence/participant stores are pod-local (`createParticipantsStore()`), and
the Socket.IO Redis adapter covers neither the **raw-ws stack** (`runtime.wss`)
nor presence. Two replicas today ⇒ boards where users see ghosts/no updates
depending on which pod they land on.
**Disposition (02):** API ships `replicas: 1`; multi-replica is gated behind an
explicit checklist (adapter for both stacks, presence externalization, load
test) — moved from a footnote to the Deployment section itself.

## HIGH

### H1. Heavy `/health` as readiness = self-inflicted total outage · *fixed*
`/health` aggregates Postgres + Redis + dirty-backlog. A Redis blip would flip
every pod unready simultaneously — turning degraded into fully-down.
**Disposition (02):** added `/health/ready` (process + Postgres only) as
readiness; `/health/live` (process-only) as liveness; Redis stays out of probe
paths; `/health` remains informational.

### H2. Two competing role mechanisms · *fixed*
Doc 01 used `--role=api` argv, doc 02 manifests set `PROCESS_ROLE` env.
**Disposition:** standardized on `PROCESS_ROLE` env var everywhere; argv form
removed.

### H3. Rollback-by-git-revert silently assumes DB backward compatibility · *fixed*
Nothing governed schema evolution; drizzle down-migrations are unmaintained in
practice. Reverting an image against a newer schema breaks.
**Disposition (README ADR-9 + 04):** expand/contract discipline is now a merge
gate: every migration must be compatible with the *previous* image; destructive
changes require a two-release dance.

### H4. "Zero-downtime websocket rollout" was asserted, not earned · *softened*
SIGTERM drops established sockets; surge pods don't help existing connections;
in-flight mutation batches can drop unless client reconnect/resync is proven
(Yjs recovers, but only if tested).
**Disposition (02):** exit criterion rewritten: measure reconnect success +
mutation-loss rate under load; graceful-shutdown sequence is a hard prerequisite
with `terminationGracePeriodSeconds: 60`.

### H5. "Scale workers on queue depth" named a metric nobody collects · *fixed*
No KEDA/prometheus-adapter anywhere in the plan.
**Disposition (02/05):** KEDA named as the mechanism (RabbitMQ queue-length
scaler in M1); HPA-on-custom-metric dropped until KEDA exists.

### H6. Outbox grows forever; dedupe story half-specified · *fixed*
No retention policy; at-least-once dispatch implies duplicates that only RMQ
consumers were told to handle.
**Disposition (01/05):** outbox pruning job (published rows purged after 7 days);
consumer-inbox dedupe made mandatory for **all** broker consumers incl. Kafka.

### H7. Rolling deploys create publisher/consumer version skew · *fixed*
New publishers + old consumers (and vice versa) coexist for minutes; nothing
governed payload evolution.
**Disposition (05):** commands/events carry `v` field; consumers must accept
N and N−1; contract tests added to CI.

### H8. Terraform chicken-and-egg + copy-paste envs · *fixed*
State bucket/lock table creation unowned; `envs/staging` and `envs/prod`
duplicated whole configs → drift magnet.
**Disposition (03):** one-time `scripts/bootstrap-tfstate.sh` committed; layout
switched to shared root modules + per-env `.tfvars`.

### H9. Secrets lifecycle hand-waved ("written out-of-band") · *fixed*
Who writes them, rotation, break-glass — unspecified.
**Disposition (03/04):** committed `scripts/secrets-write.sh`; rotation table
(JWT 90d, DB creds quarterly, Stripe/Google on vendor rotation); RDS master
password generated by Terraform into Secrets Manager; break-glass procedure
documented.

### H10. RPO never stated — silent CRDT data-loss window · *accepted, documented*
Redis AOF loss (pod reschedule, node loss) erases unflushed board ticks. On the
current single host this risk already exists; K8s StatefulSets don't reduce it.
**Disposition (README ADR-10 + 02):** explicit RPO decision: staging accepts
loss ≤ flush interval; prod requires managed Redis with `appendfsync
everysec` + documented flush-interval SLO; loss window monitored via
`timeSinceLastDirtyMs` (already exposed by `/health`).

### H11. DB cutover downtime unquantified · *fixed*
"Dump/restore in a maintenance window" hid the real number for a live realtime
product.
**Disposition (03):** sizing formula (~1–2 min/GB restore + smoke tests),
cutover runbook steps, rollback = repoint env var; dual-write explicitly
rejected (CRDT merge complexity outweighs benefit at this scale).

## MEDIUM

### M1. Phase 0 directory reshuffle = repo-wide rewrite PR for marginal gain · *descoped*
Moving every route/service into `src/modules/*` collides with active
development and buys nothing before K8s.
**Disposition (01):** split into 0A (enforce seams on current layout — done
first, small diffs) and 0B (physical move, optional, deferred until seams are
stable).

### M2. InMemoryEventBus allowed phantom events · *fixed*
Inline emission inside a failing transaction publishes ghosts.
**Disposition (01):** rule added — domain events publish only **after commit**
(`emitAfterCommit` helper); durability-critical flows go through the outbox.

### M3. Cost/premise gap: ~$20/mo VPS → $500–800+/mo cloud, unchallenged · *fixed*
Plan assumed EKS/Terraform/ArgoCD without stating team size, SLOs, or budget.
**Disposition (README):** added "Premise gates" requiring written SLOs + budget
sign-off before phase 2, plus a lighter alternative path (single managed
cluster or PaaS) recorded as a legitimate outcome.

### M4. Activity-based exit criteria · *fixed*
"X deployed" replaced with outcome checks where feasible (reconnect rate,
reproduce-staging timing, lag thresholds, DLQ alarms).

### M5. Supply-chain hardening absent · *added*
No image signing/SBOM, `latest` unpinned addon URLs, zero NetworkPolicies.
**Disposition (02/README conventions):** immutable `:sha` tags + cosign verify
admission, pinned tool URLs, default-deny NetworkPolicy task listed.

### M6. PDB declared but never specified · *fixed*
Content shown in 02; interplay corrected (`maxUnavailable: 1`, not
`minAvailable`, so single-replica voluntary drains still work).

### M7. Referenced-but-undefined resources · *fixed*
ClusterSecretStore YAML and AppProject RBAC snippet added (04).

### M8. Prod tracking `main` = permanent OutOfSync noise · *fixed*
Prod overlay now tracks a `releases/prod` ref bumped only by promotion PRs (04).

### M9. Workers share the API's resource class · *fixed*
Distinct requests/limits for CPU-bound preview rendering (02).

### M10. Two deploy sources of truth during transition · *fixed*
Compose `deploy`/`setup-ssl` recipes get an explicit deprecation step + removal
gate after phase-2 cutover (README conventions).

## LOW (noted, not blocking)

- Prometheus scrape annotations existed only on the API pod template — workers
  added (02).
- `just` recipe naming mismatch (`lint:arch` npm vs `lint-arch`) — unified (01).
- Unpinned `cert-manager .../releases/latest/download` URL — pinned version (02).
- Heartbeat timer placement after role split — covered by role-boot matrix test
  in 01 exit criteria.

## Rejected findings (kept as-is)

| Finding | Why rejected |
|---|---|
| "Skip modular monolith, go straight to services" | CRDT shared state + team size make premature splits net-negative |
| "Use Helm instead of Kustomize" | Kustomize suffices at this scale; chart drift costs exceed template benefits |
| "Debezium CDC from day one for outbox" | Poller meets current throughput; CDC is an upgrade path, not a prerequisite |
| "Sticky sessions required for Socket.IO" | Transport is websocket-only (no polling upgrade hop); stickiness isn't the blocker — pod-local stores are (C7) |
